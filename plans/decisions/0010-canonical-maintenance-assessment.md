# ADR 0010: Canonical maintenance composition and operation boundaries

Status: accepted for I09b, 2026-09-24.

One read-only assessment composes release/resource inventory, existing discovery
outcomes and available canonical CI check reports. Four dimensions remain explicit;
an update does not subsume customization, repository-fit or integration findings.
`maintenance_facts.py` translates facts into typed dimension outcomes and actionable
recommendations. `maintenance.py` owns bounded observation, consistency replay and
post-operation comparison. `maintenance_operations.py` rechecks the assessment
before delegating compatible candidates to the existing protected pack preview.

Accepted profile constraints determine required status. An unverified lock cannot
turn its recorded ownership/version claims into mandatory file/version violations.
Missing publisher or integration evidence remains unknown, and an available update
is normally advisory. Discovery changes cannot accept architecture or capabilities.
CI results reuse I04 normalization and must match repository/profile/resolution/lock,
complete Git identity, repository scope and accepted assessment age. Their own
required flags cannot relax accepted obligations. I10 still owns live provider
collection and generated integration repair; files or synthetic pilots are not
active-enforcement evidence.

The versioned assessment preserves input snapshots, evidence, source/lookup times,
baseline and resource identity, derived check results, stable recommendations,
prerequisites, affected resources/controls and uncertainty. Record replay checks
internal consistency, not authenticity. A candidate preview recomputes observed
inputs and freshness; it never executes a saved action list or downloads code.
Other actions name their owning review workflow and remain unready for execution.

Migration previews embed the canonical assessment; optional saved assessments bind
explicit evidence. Existing digest acceptance, protected application and rollback
remain authoritative. After application, existing conformance and maintenance run
again. A disappeared recommendation is resolved only if its dimension passes under
unchanged accepted policy/identity; changed-policy or incomplete evidence stays
unverified. A marker change alone is not remediation.

Bounded snapshots, ignored/unreadable content and concurrent writers remain explicit
limits. Saved assessments are limited to 16 MiB. No network, check execution, policy
acceptance, repository mutation or telemetry is added to default assessment.
See [the assessment guide](../../docs/MAINTENANCE_ASSESSMENT.md) for the public contract.
